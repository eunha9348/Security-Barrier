# ADR-001: Dummy-data dilution 및 "가중치 낮추기"를 완화책으로 채택하지 않음

- 상태: **기각** (대안 2건 채택)
- 일자: 2026-09-13
- 맥락: [PRIOR-ART.md §2](./PRIOR-ART.md) — "LLM이 잊게 만들기"가 스킬 레이어에서 불가능하다는 결론의 후속 검토

## 제안된 안

보안 자료가 컨텍스트에 유입된 뒤 삭제가 불가능하다면,
(a) 해당 자료의 **가중치를 최하로** 떨어뜨리고
(b) **Dummy data로 희석(dilute)** 하여 실질적 무력화를 노린다.

## 기각 사유

### (a) "가중치 최하" — 조작할 핸들이 존재하지 않음

- 스킬은 프롬프트와 스크립트다. **어텐션 가중치에 접근할 수 있는 인터페이스가 없다.**
- 토큰 단위 억제(logit bias)는 Messages API에 존재하지 않는다. 그뿐 아니라
  [Claude Opus 4.6 이후 모델은 `temperature`/`top_p`/`top_k`조차 거부](https://platform.claude.com/docs/en/api/messages/create)한다
  (기본값 외 지정 시 400). **샘플링 조작 경로 자체가 닫혀 있다.**
- "이 내용은 무시하라"는 프롬프트 지시는 내용을 컨텍스트에 **유지한 채** 주의만 환기시킨다.
  제거가 아니라 강조에 가깝다.
- 유일하게 실재하는 "가중치 낮추기"는 **컨텍스트에서 실제로 빼는 것**
  ([context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing))이며, 이는 희석이 아니라 삭제다.

### (b) Dummy dilution — 정보를 제거하지 않고 추가할 뿐

1. **정보이론적으로 무효.** 희석은 진짜 데이터의 정보량을 줄이지 않는다. 총량만 늘린다.
   원본은 여전히 컨텍스트·전사·로그에 **완전한 형태로** 존재한다.
2. **외부 오라클로 즉시 분리된다.** 크리덴셜은 사용해 보면 되고, 문서는 원본과 대조하면 된다.
   더미를 진짜와 구분 불가능하게 만드는 문제(flatness)는 **honeywords**
   ([Juels & Rivest, CCS 2013](https://dspace.mit.edu/bitstream/handle/1721.1/90627/Rivest_Honeywords.pdf))가
   10년 넘게 풀지 못해 주요 인증 플랫폼에 채택되지 못한 바로 그 문제다.
3. **실증 반례 존재.** [Privacy Failure in Split-LLM Training (arXiv:2609.04382)](https://arxiv.org/abs/2609.04382):
   실제 행과 디코이를 섞었으나 손실이 디코이를 무시해 **그래디언트가 정확히 0**이 되었고,
   그 0의 패턴만으로 실제 행이 전부 식별되었다 — **9개 시드에서 프레임당 4,096/4,096 전량 적중.**
   디코이 방어는 의도치 않은 부채널로 무너진다.
4. **노이즈 추가는 복원 가능하다.**
   [단어 단위 DP 새니타이즈조차 주변 문맥으로 원문이 재구성된다](https://arxiv.org/pdf/2508.18976).
   희석은 DP보다 약한 보장이다.
5. **확률적 저하는 통제가 아니다.** 디스트랙터가 검색 성능을 떨어뜨린다는 NIAH 계열 결과는 존재하지만,
   이는 평균 정확도의 하락이지 접근 차단이 아니다. 보안 통제로 쓸 수 없다.
6. **자기 파괴적이다.** 더미를 뿌리는 순간 자사 DLP 스캐너·감사 로그·시크릿 스캐너가 전부 오염된다.
   경보 피로를 유발해 **진짜 사고의 탐지율을 떨어뜨린다.**
7. **정당 사용자의 효용도 함께 붕괴한다.** 모델은 진짜와 더미를 구분하지 못하므로
   업무 질의에 대해서도 잘못된 값을 반환하게 된다.
8. **검증 불가능하다 — 프로젝트 규칙 R2/R3 위반.**
   "희석되었다"를 입증할 메트릭이 없다. 증거 없이 완화를 보고하는 순간
   그것이 곧 이 프로젝트가 금지한 hallucination이다.

## 채택한 대안

### 대안 1 — 출력측 교정 (CURE 방식): PURGE 이후 잔존분에 대한 2차 방어

[CURE: Corrective Unlearning with Retrieved Exclusions (arXiv:2509.25973)](https://arxiv.org/abs/2509.25973)

- 경량 corrector가 **출력을 검증하고 누출이 탐지되면 재작성**한다.
- 제외 대상을 **검색해 in-context 레퍼런스로 제공**하므로 추가 학습 없이 신규 요청에 적응한다.
- 연속적 언러닝 요청에 강건하며, 간접 질의에서의 누출까지 줄인다.
- 근거 보강: [Guardrail Baselines for Unlearning in LLMs (arXiv:2403.03329)](https://arxiv.org/abs/2403.03329) —
  프롬프트·입력필터·출력필터 같은 **단순 가드레일이 파인튜닝 언러닝과 대등한 성능**을 낸다.

> 차이의 핵심: 희석은 **은폐**를 시도하고, CURE는 **출력 경로를 차단**한다. 후자는 검증 가능하다.

### 대안 2 — Dummy를 은폐가 아니라 탐지에 사용: Canary / Honeytoken

- 가짜 보안문서·가짜 크리덴셜을 **Security Axis에 등록된 카나리**로 심는다.
- 그것이 모델 출력이나 외부 채널에 나타나면 = **유출 확정 신호.**
- 카나리는 심은 곳 외에는 존재할 수 없는 문자열이므로 **구조적으로 오탐이 0이다.**
- 직접 유사도 탐지가 실패하는 패러프레이즈·번역·부분 추출 상황에서도 동작한다.

> 더미 데이터의 유일하게 건전한 용법이다. 발상의 방향만 뒤집으면 된다.

## 파이프라인 반영

```
BREACH
 ├ REVERSE / FORWARD TRACE
 ├ PURGE       파생물 → 원본, tombstone
 ├ SUPPRESS    ← 신규. CURE식 출력 corrector. 제거 불가 잔존분 대상
 │              ※ "차단"이 아니라 "완화"로만 보고할 것 (R4 유지)
 ├ VERIFY      재탐지 0-hit + 해시 대조
 ├ ROTATE      크리덴셜은 삭제 불가 전제
 └ REPORT      도달 불가 영역 명시
```

Security Axis 스키마에 `canaries:` 섹션을 추가한다 (대안 2).
